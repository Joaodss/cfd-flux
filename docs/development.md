# Development environment

## Requirements

| Tool | Version | Used for |
|------|---------|----------|
| Rust (rustup) | ≥ 1.85 (tested with 1.90) | `crates/` workspace |
| Node.js | ≥ 22 (tested with 24) | `apps/web` |
| CUDA Toolkit | 13.x (tested with 13.4) *(used from Phase 2b)* | `cfd-cuda` backend (NVRTC) |

**Author's machine (verified 2026-10-09):** RTX 4060 8 GB (`sm_89`), driver 610.62 (supports CUDA 13.3),
CUDA Toolkit 13.4, VS Build Tools 2022 (MSVC 14.4x), Rust 1.90 `stable-x86_64-pc-windows-msvc`, Node 24.
Native `cargo build/test` and a CUDA test kernel (`nvcc -arch=sm_89`) both work.

### CUDA on Windows — notes

- `nvcc` needs the MSVC environment loaded: use the "x64 Native Tools Command Prompt for VS 2022" or
  call `vcvars64.bat` first. Outside that environment it fails with `nvcc fatal: Host compiler targets unsupported OS`.
- In CUDA 13 the DLLs (including `nvrtc64_*.dll`) live in `CUDA\v13.4\bin\x64`, which must be on the PATH
  for `cudarc` to load them.
- **Driver (13.3) older than the toolkit (13.4):** binaries compiled for `sm_89` (SASS/cubin) work; PTX
  generated by NVRTC 13.4 may be rejected by the driver's JIT. In Phase 2b, have NVRTC compile straight to
  cubin (`-arch=sm_89`) or update the driver.

### Windows: Rust toolchain

Recommended (and in use): the **MSVC** toolchain (`stable-x86_64-pc-windows-msvc`) with **Visual Studio Build Tools 2022**
and the "Desktop development with C++" workload. It is Rust's default toolchain on Windows, and CUDA on
Windows needs the MSVC C++ compiler as well.

```powershell
winget install Microsoft.VisualStudio.2022.BuildTools --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
rustup default stable-x86_64-pc-windows-msvc
```

> **Resolved issue (2026-10-09)** by switching to MSVC — kept for reference: with the `windows-gnu` toolchain and the old
> MinGW.org in `C:\MinGW\bin` on the PATH, `cargo build` fails in `windows-sys` ("Dlltool could not create import
> library") because there is no x86-64 assembler. `cargo check`/`clippy` still work; to build/test use the MSVC
> toolchain (above) or WSL.

### Alternative: WSL (Ubuntu)

```bash
cd /mnt/c/Users/<user>/Desktop/GithubProjects/live-fluids
CARGO_TARGET_DIR=$HOME/.cache/live-fluids-target cargo test --workspace
```
(A `CARGO_TARGET_DIR` outside `/mnt/c` avoids mixing Windows/Linux artefacts and is much faster.)

## Commands

```bash
# Rust
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# Scene format: after changing crates/cfd-core/src/scene.rs or examples.rs
cargo run -p cfd-cli -- schema schema/scene.schema.json
cargo run -p cfd-cli -- example --all scenes
cd apps/web && npm run gen:types

# Check scene files
cargo run -p cfd-cli -- validate scenes/*.json

# Run a scene headless (frames, PNGs, CSV series, meta.json); re-render PNGs with other ranges
cargo run --release -p cfd-cli -- run scenes/cylinder-re100.json --out out/cyl --end-time 12 --output-interval 0.05
cargo run --release -p cfd-cli -- render out/cyl --range vorticity=-50:50

# Performance (results go to docs/benchmarks.md) and physics validation (docs/08-validation-guide.md)
cargo run --release -p cfd-cli -- bench --threads 8
cargo run --release -p cfd-cli -- verify --quick            # CI subset, ~1 min
cargo run --release -p cfd-cli -- verify --full             # writes validation/report/ (commit it)
cargo run --release -p cfd-cli -- verify --cases cavity --no-report

# Web (in apps/web)
npm install
npm run dev          # development server
npm test             # Vitest (checks scenes/ against the JSON Schema)
npm run typecheck && npm run lint && npm run format:check && npm run build
```

## Conventions

- **Everything in English** — code, identifiers, comments, docs, UI text and commit messages ([ADR-013](07-decisions-and-questions.md)).
- `schema/scene.schema.json`, `scenes/*.json` and `apps/web/src/generated/` are **generated** — do not edit them by hand.
  The Rust tests and the web CI fail if they are out of date.
- Work on branches and merge into `master` through pull requests; CI must be green.
