# CLAUDE.md

cfd-flux — web CFD simulator: pixel editor in the browser → local Rust server → GPU solver (CUDA and wgpu) with CPU fallback. Status: **Phase 4 complete** (web editor in `apps/web`: WebGL2 canvas, drawing tools, tile-swap undo, palette with automatic elements, property panels, `cfd_core::library`, `.cfdscene` files with `deflate+base64` layers, server save/open, autosave, PNG import, gallery, server-side validation with issue `params`/`at`, Run and the job view; ADR-030; Playwright acceptance test in CI), on top of **Phase 3 complete** (server and jobs; LFFR v2 frame codec; on-device sampling, ADR-028; `skip_macro`, ADR-029), on top of **Phase 2 complete**: Phase 0 foundations (scene format, validation, frames, CLI, web skeleton), `Scene → Domain`/units (`cfd-core`), the CPU LBM solver (`cfd-lbm`, the numerical reference), the wgpu/WGSL backend (`cfd-gpu`; layout and async stepping in ADR-019/020), the CUDA backend (`cfd-cuda`, bit-identical to the CPU; ADR-021), kernel constants generated by `cfd_lbm::abi`, parity cases shared in `cfd_verify::parity`, `cfd-cli run/render/bench/verify` (`--backend auto|cpu|wgpu|cuda`), the backend-agnostic validation suite (`cfd-verify`, reports in `validation/report/`, `report-wgpu/`, `report-cuda/`) and the engine comparison (`cfd-cli compare`, `bench --backends`; `cfd_verify::compare`, ADR-023, report in `validation/compare/`). Phase 3 so far: `cfd-engines` (engine selection, device inventory) and `cfd-job` (command loop, output thread, result layout) shared by the CLI and `cfd-server` (axum + SQLite, per-device job slots, WebSocket streaming; ADR-024–027), `cfd-cli submit` (test client), the LFFR v2 frame codec (byte shuffle + lz4, Q13), on-device output sampling (`Solver::request_samples`) and `skip_macro`; next: Phase 5 (visualisation: the viewer in the job view).

- Documentation lives in `docs/` (index in `README.md`). Read `docs/05-implementation-plan.md` before starting any phase; commands and environment are in `docs/development.md`.
- Language: **everything in the repository is in English** — code, comments, docs, UI text, commit messages (the project is part of the author's English CV/portfolio). The author may chat in Portuguese; reply in their language, but write repository content in English.
- Decisions and open questions: `docs/07-decisions-and-questions.md` — update it when the author answers or a decision changes.
- Scene format: source of truth is `crates/cfd-core/src/scene.rs`. `schema/`, `scenes/` and `apps/web/src/generated/` are generated (`cfd-cli schema`, `cfd-cli example --all scenes`, `npm run gen:types`); tests fail if they are out of date.
- Author: strong CFD background (don't explain basic physics), little Rust/GPU experience, comes from C# → explain Rust/wgpu/CUDA idioms when relevant, with C# parallels. The prototypes in `sandbox/` are for the author to learn with: don't write them unless asked.
- Local environment (Windows): Rust MSVC toolchain (native build/test OK), VS Build Tools 2022, CUDA Toolkit 13.4 (driver 617.42 = CUDA 13.4 since 2026-10-12; `cfd-cuda` compiles `sm_89` cubins, not PTX), RTX 4060 8 GB. Details in `docs/development.md`. Repository: github.com/Joaodss/cfd-flux, branch `master`.
- Working rules:
  - Three backends: CPU (numerical reference), wgpu/WGSL and CUDA (`cfd-cuda`, `cuda` feature). Every GPU kernel needs a parity test; keep the same memory layout in all three.
  - Every new solver must pass the validation cases in `docs/04-numerical-methods.md` §7 (method in `docs/08-validation-guide.md`).
  - Physical units in the scene; conversion to lattice units only in the solver.
- When finishing plan tasks, tick their checkboxes in `docs/05-implementation-plan.md`.
